# Path: team org

For a user whose commit history shows collaborators. Goal state: an org
with the user as founder and real invitations in their teammates' hands.

1. Found with a real org name (not "personal") — renaming later is not the
   smooth path.
2. After identity, open the dashboard's organization surface and mint
   invitations. Per-invite choices that matter: role (default member),
   one-time vs open link, and binding (bearer links always require an
   approval on redemption — a leaked link at worst produces a request).
3. Each teammate's invitation is itself an install: the invite link opened
   without a local node offers this same document to THEIR agent. That's
   the loop you're now part of.
4. Approvals are asynchronous and threshold-based (roles can require more
   than one approver). Show the user where pending claims appear.

Done when: at least one invitation is delivered and the user knows where
approvals land.
